Remote Access Setup — Hikvision

GS Electrical · installer reference for configuring kit you've installed, from off-site.

The ground rules Only for devices you installed / are contracted to maintain, with the customer's knowledge and consent, using credentials you legitimately hold. Remote access needs a valid admin login — if the password is lost, that's a local SADP reset on site (can't be done remotely, by design). Log the customer's consent to remote-manage in your job notes.

Option A — Hik-Connect (recommended default)

Easiest · no router changes

Hikvision's cloud relay (P2P). The device dials out to Hik-Connect, so you reach it without opening anything on the customer's router.

  1. On site (or via existing local access): Configuration → Network → Advanced → Platform Access, tick Enable, platform Hik-Connect, set a verification/stream encryption code.
  2. Make sure the device has a working internet connection and correct gateway/DNS.
  3. Add the device to your installer account in the Hik-Connect app / iVMS-4200 / Hik-Partner Pro by serial + verification code — or have the customer add it to their account and Share it to you.
  4. From home: open Hik-Connect (app or desktop) or iVMS-4200 and the device is there to view and configure.

+ No ports exposed to the internet. + Survives changing home IPs. + Customer can revoke sharing anytime.

− Relies on Hikvision's cloud being up. − Some deep settings are still easier over the full web UI (use VPN for those).

Option B — VPN into the site network

Most secure direct access

If the customer's router supports it (many do — WireGuard/OpenVPN/IPsec), set up a VPN once. You then join their LAN from home and reach the camera's full web UI exactly as if you were on site — SADP won't traverse it, but the web interface and iVMS will.

  1. Enable the router's VPN server (or add a small VPN box), create a client profile for yourself.
  2. Connect from home, then browse to the device's local IP (e.g. https://192.168.1.64) or add it in iVMS-4200 by LAN IP.

+ Nothing camera-facing is exposed to the internet. + Full config access. + One tunnel covers every device on site.

− Needs a capable router or a VPN device. − Slightly more to set up the first time.

Option C — DDNS + port forwarding

Works, but exposes the device — harden it

Direct route: a DDNS hostname tracks the customer's changing public IP, and the router forwards a port to the device so you can reach its web UI / iVMS from anywhere. Because it puts the device on the public internet, only do this with the hardening below.

  1. Set up DDNS (router's own, or the device's Network → DDNS).
  2. Forward a non-default external port to the device's HTTPS port; prefer HTTPS, avoid plain HTTP.
  3. Reach it from home at https://yourname.ddns.net:PORT.

If you do this: strong unique admin password, latest firmware, HTTPS only, change default ports, disable services you don't use (UPnP, old ONVIF, Telnet/SSH), and lock the forward to your own IP if the router allows. Prefer A or B whenever you can.

If the password is lost (not remote)

None of the above helps if you've lost the admin login — remote password reset is deliberately blocked. You'll need someone on the local network with the SADP tool: either a site visit, or talk the customer through running SADP and reading you the serial + Start Time so you can generate the reset code (see reset-code-generator.html / site-prep.html). The code is then entered in SADP on their LAN.

Prefer Hik-Connect or VPN. Port-forwarding a camera straight onto the internet is the most-attacked setup there is — only with the hardening above.
